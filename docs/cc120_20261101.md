# CC120のチャンネル別停止（2026-11-01）

MIDI CC120（All Sound Off）で全チャンネルを止めていた処理を、指定チャンネルだけの停止へ変更した。
押下中・Sustain保持中・Release中のvoiceをミュートし、PMON時はcarrierとmodulatorの両方を停止する。
他チャンネルの波形・envelope・bend /pedal、voice allocatorの進行を保持する。

実装は`0bb1bb7`、作業前TODOは`8f03fdd`、開始Pluginは`faa8922`。
Native SDKは`95cf71a`のまま。parameter ID0〜25 /state schema9 /Gain範囲は変更していない。
source /binary /log hashとCIは[JSON記録](cc120_20261101.json)を参照。

## 停止の範囲

- CC120は対象channelのdry voiceをvolume0＋KOFFで停止する。NoteOffやCC123のように
  SustainやADSRのRelease完了を待たない。空slotと不正channelは変更しない。
- 共有Reverb historyは保持する。既に蓄積された残響をchannelごとに分離して消すことはせず、
  他チャンネルとともに自然減衰を続ける。
- causal rate adapterも保持する。44.1kHzではMIDI offset直後からdry0となり、
  他rateでは保持済みmixed sample historyが約2 native sample間隔だけ残り得る。
  他チャンネルの位相を変えるようなglobal history resetは行わない。
- 停止した物理voiceは次のNoteOnでfresh latchする。古いaudition restartやreleaseを再発音しない。
- CC120ではbend /pedal値と後続MIDIを保持する。同offsetのCC120→NoteOnは入力順に処理し、
  新しいNoteOnを演奏する。CC121 /CC123、overflow /reset /restore /bypassの既存cleanupも維持する。

## UIの全停止

画面の**All sound off**は、引き続き全チャンネルと共有Reverb tailを停止する。
以前のCC120 channel0送信から、UI MIDIとglobal stopを同じ固定容量FIFOへ送る方式に変更した。

別のatomic flagだけでglobal stopを渡すと、frameworkのUI MIDI drain直後に入った古いNoteOnが
次blockで鳴り直すraceがあるため、UI入力とstopの順序を同じFIFOで保証する。
stop以前のpending notesを破棄し、stop後の新しいUI NoteOnは演奏する。
controller eventsは保持する。UI commandは1blockにつき先頭で取得したsnapshot件数だけ処理する。

FIFOは1024件、UI single producer /audio single consumer、固定配列とlock-free atomicを使用する。
overflow時はpending入力を破棄し、既存の全停止・controller resetへ戻してNoteOff欠落による鳴り残りを防ぐ。
reset /成功restore /deactivate /bypassでは既存pending UI入力も破棄する。
host MIDIの非render-thread受信全般への対応を追加したものではなく、従来のserialized ingress前提を維持する。
host restoreはaudio processingを止めたquiescent lifecycle呼出が前提。
